# סטודיו עיצוב

אפליקציית Next.js ליצירת עיצובים מקטגוריות ותמונות. השלב הנוכחי: ניהול קטגוריות ותמונות ועורך ידני (בלי AI).

## הרצה

```
npm install
npm run dev      # http://localhost:3000
```

הנתונים נשמרים מקומית בתיקייה `data/` (קובץ `db.json` ותיקיית `uploads/`). התיקייה לא נכנסת ל-git.

## משתמשים והרשאות

**ההתחברות פעילה.** לפיתוח בלבד אפשר להריץ עם `AUTH_DISABLED=true`: כל מבקר הוא אז אורח אנונימי שנזכר לפי עוגייה בדפדפן, ויכול לעבור ל"מצב ניהול" בכפתור בסרגל העליון. בבילד של פרודקשן ההגדרה הזו לא פועלת.

- נרשמים ב-`/login`. **מנהל הוא רק מי שנרשם עם האימייל שב-`ADMIN_EMAIL`**, ולכן מגדירים את המשתנה לפני ההרשמה.
- מנהל: בונה תבניות, מסמן אילו טקסטים הלקוח יכול לערוך (ומה שם השדה), מפרסם או מבטל פרסום, מנהל קטגוריות ותמונות.
- לקוח: רואה תבניות שפורסמו, מתחיל מהן כרטיס משלו ועורך בו רק את השדות שסומנו. ההגבלה נאכפת בשרת (`applyCustomerEdits` ב-`src/lib/canvas.ts`), לא רק בממשק.

## מבנה

- `/categories` — יצירת קטגוריות, העלאת תמונות לכל קטגוריה (גרירה או בחירה), שינוי שם ומחיקה.
- `/` — רשימת העיצובים ויצירת עיצוב חדש (A4, A5, ריבוע, סטורי).
- `/editor/[id]` — עורך קאנבס: טקסט (עברית RTL), מלבנים ותמונות מהקטגוריות; גרירה, שינוי גודל, סיבוב, שכבות, שכפול, ביטול/חזרה, שמירה אוטומטית וייצוא PNG ב-300dpi.

## קבצים מרכזיים

- `src/lib/types.ts` — מבנה הנתונים ומסמך הקאנבס (מידות במ״מ).
- `src/lib/canvas.ts` — ולידציה של מסמך הקאנבס, גדלי עמוד ופונטים.
- `src/lib/db.ts` — שכבת האחסון המקומית. כל הגישה לנתונים עוברת דרכה, כדי שאפשר יהיה להחליף ב-MongoDB ו-Cloud Storage לפי האפיון.
- `src/components/Editor.tsx` — העורך.
- `examples/ad-import/` — כלי להמרת מודעות שטוחות (JPG) לתבניות עם טקסטים שאפשר לערוך, עם שתי מודעות לדוגמה.

## ערכת מותג לעסק

ב-`/business/brand` עסק שומר לוגו, צבעים ופרטים (`src/lib/brand.ts`, ערכה אחת לכל משתמש). מנהל מסמן בעורך אילו אלמנטים בתבנית מקבלים פרט, צבע או לוגו מהערכה. בדלת העסקית העיצובים מוצגים עם המיתוג של המשתמש, והעותק שנפתח מקבל אותו בשרת (`useBrand` ב-`POST /api/projects`). לוגו נשמר כתמונה בקטגוריה פרטית של בעליו (`brand:<userId>`), ו-`visibleImages` מסתיר אותו ממשתמשים אחרים.

### לוגו

בקטגוריה "לוגו" עסק בוחר תבנית, והשם והצבעים מתמלאים מהערכה. הכפתור "זה הלוגו שלי" בעורך שומר את העיצוב כ-PNG בלי רקע ובלי שוליים ומכניס אותו לערכה.

## מודעות והודעות לפי מקצוע

`src/lib/professions.ts` מחזיק לכל מקצוע את כאבי הלקוח, ההצעות, מה אסור לטעון, נוסחי המודעות והודעות הפרסום. **הנוסחים הם טיוטה, והלקוח צריך לאשר אותם**, במיוחד במשכנתאות.

- **סדרה:** תבניות עם אותו שדה `series` נלקחות יחד לסלסלה (`POST /api/projects/series`).
- **הודעות:** ב-`/business/messages` העסק מתאים הודעה ומעתיק אותה. האתר לא שולח שום דבר בשם העסק.
- **צבעים קריאים:** תפקידי הצבע `onPrimary` ו-`onSecondary` נותנים שחור או לבן לפי הצבע של העסק.

## התהליך העסקי

התהליך המרכזי הוא מיתוג, מקצוע, גלריה, עורך והורדה. הכול סביבו משתמש באותם נתונים.

- **ניסיון לפני הרשמה:** בעמוד מקצוע מקלידים שם וטלפון, וכל המודעות מצטיירות איתם בדפדפן. הפרטים נשמרים ב-`localStorage` (`src/lib/brandDraft.ts`), והופכים לערכת המותג אחרי ההרשמה.
- **בדיקת מודעה:** `src/lib/adCheck.ts` רץ בעורך על כל שינוי. ממצא מסוג `must` עוצר הורדה עם חלון שאפשר לעבור אותו, כי ההחלטה נשארת של העסק. הבדיקה לא נאכפת בשרת.
- **מידות:** `src/lib/adFormats.ts` מגדיר מידות לטלפון ולדפוס. כל מודעה קיימת בכל מידה, כתבניות עם אותו `sizeGroup`, ורק זו שיש לה גם `series` מוצגת בגלריה עד שבוחרים מידה. בעורך אפשר לעבור מידה בלי לאבד נוסח ותמונה (`POST /api/projects/[id]/resize`).
- **PDF לדפוס:** הקובץ בגודל האמיתי וב-300dpi (`src/lib/pdf.ts`). הוא בלי שוליים לחיתוך (bleed) וב-RGB, אז לעבודות שמגיעות עד הקצה כדאי לשאול את בית הדפוס.
- **על העסק וקטלוג:** `BrandKit.profile` ואוסף `catalog` (`/business/catalog`) הם גם המקור היחיד של העוזר לעובדות על העסק (`src/lib/businessBrief.ts`). פריט מהקטלוג מחליף את הכותרת, המשפט והתמונה במודעה, ומסיר את רשימת הנקודות הכללית של התבנית.
- **"תכינו לי מודעה":** תוספת לצד הגלריה (`POST /api/compose`). משפט אחד נותן 3 ניסוחים לאישור ולעריכה, ורק הניסוח שאושר מצטייר על העיצובים. לא נשמר כלום עד שבוחרים אחד. **בחינם כרגע**, עם מכסה יומית למשתמש ב-`COMPOSE_DAILY_LIMIT` (ברירת מחדל 20), כי כל בקשה עולה בקריאה למודל. ניסוח עם מספר שלא נמסר על ידי העסק נזרק בשרת (`backedByFacts`).
- **מה העסק מוסיף בעצמו:** במודעה הוא יכול להוסיף טקסטים משלו, להחליף את התמונה, ולהעלות מדבקות מקובץ. הכללים נאכפים בשרת (`applyCustomerEdits` עם `FreeEdits`, דרך `src/lib/customerSave.ts`), והם לא חלים על כרטיס פרטי. תמונות ומדבקות של עסק נשמרות בקטגוריה הפרטית שלו ולא נראות לאחרים.
- **הסרת רקע:** `src/lib/removeBackground.ts` מסיר רק רקע אחיד, ובתמונה אחרת עונה null ולא חותך. ספרייה כמו `@imgly/background-removal` היא AGPL, אז לתמונות מורכבות צריך לבדוק קודם רישיון.
- **רצועת פרטים:** `src/lib/strip.ts` מוסיף למודעה אייקונים, כתובת, אתר וקוד QR לפי מיקום הטלפון בתבנית, כך שזה מתאים לכל פריסה ומידה. ה-QR נוצר בשרת כשערכת המותג נשמרת (`src/lib/brandQr.ts`), והוא אופציונלי. האייקונים הם תמונות בספרייה עם מזהים קבועים, וצריך להריץ `npm run seed:content -- --only=business` כדי שיהיו.
- **מבצעי החודש ותבנית אישית:** תבנית מסמנת אזור מוצרים (`role: 'productArea'`), ו-`src/lib/products.ts` פורס בו עד 20 פריטי קטלוג. אותו קוד רץ בדפדפן ובשרת, והשמות והמחירים נלקחים מהקטלוג של הבעלים בלבד. עיצוב עם `keep` נשאר תבנית של העסק, ובסלסלה פותחים ממנו מודעה חדשה (`{ fromDesign }`).

## פונטים וייבוא עיצוב

- **ספריית פונטים:** ב-`/fonts` מנהל מעלה פונטים ובוחר אילו מהם מוצעים לעסקים (`CUSTOMER_FONTS` ואוסף `fonts`). עסק בוחר פונט רק לטקסט שהוסיף בעצמו, ושרת מחזיר לברירת המחדל פונט שלא הוצע לו. קובץ פונט שהאתר משתמש בו מגיע לדפדפן, אז אי אפשר להסתיר אותו לגמרי: חשוב לבדוק שהרישיון מתיר שימוש ברשת.
- **תבנית מעיצוב מוכן:** בעמוד התבניות, הכפתור "מעיצוב מוכן" שולח תמונה ל-`POST /api/templates/import`. המודל קורא את הטקסטים (`src/lib/agent/importDesign.ts`), הם נמחקים מהתמונה (`src/lib/eraseTexts.ts`) וחוזרים כשדות חיים בתבנית טיוטה. התוצאה היא נקודת התחלה לבדיקה בעורך: הפונטים הם הקרובים ביותר שנמצאו, ועל רקע לא אחיד המקום שנמחק נראה לעין. התשובה מדווחת בכמה מקומות זה קרה.

## זמני שבת

`src/lib/shabbat.ts` מחשב בשרת את השבת הקרובה לפי עיר, ו-`src/lib/shabbatDoc.ts` מחזיק את טבלת הערים. הזמנים נכתבים לעותק בשרת, והלקוח לא יכול לשנות אותם. עיצוב של שבת שעברה לא ניתן להורדה.

- **לפני השקה:** הטבלה היא טיוטה, ו**צריך אישור הלכתי לכל עיר**. החישוב היום לפי גובה פני הים, ויציאה בדקות אחרי השקיעה. לוחות מקובלים מחשבים לפעמים אחרת, ובירושלים נמצא הפרש של כמה דקות.
- **רישיון:** `@hebcal/core` הוא GPL-2.0. הוא רץ רק בשרת, ואסור לייבא אותו לקוד של הדפדפן.
- **סרטון:** `POST /api/projects/[id]/video` מרכיב ב-ffmpeg את הרקע מ-`public/shabbat/` עם שכבה שקופה מהעורך. בשרת צריך ffmpeg ב-PATH, או נתיב ב-`FFMPEG_PATH`.

## תשלום

**התשלום כבוי כברירת מחדל:** כל ההורדות חינם והמחיר רק מוצג. הוא נדלק כש-`BILLING_PROVIDER` מוגדר.

- `sandbox` הוא ספק בדיקות שלא גובה כסף. בבילד של פרודקשן הוא לא פועל, אלא אם מוסיפים `BILLING_ALLOW_SANDBOX=true`, שמיועד לבדיקה מקומית בלבד.
- **ספק אמיתי עוד לא מחובר.** ההוראות לחיבור נמצאות בראש `src/lib/billing.ts`. פרטי אשראי לא מגיעים לאתר.
- `SUBSCRIPTION_PRICE` קובע את מחיר המנוי (ברירת מחדל 149 ₪).
- **גבול האכיפה:** השרת מחליט אם מותר להוריד, אבל התמונה נוצרת בדפדפן, ולכן מי שעובד עם כלי המפתחים יכול לעקוף את זה. הסרטון נוצר בשרת, ושם אין עקיפה כזו.

## כרטיסים ונוסחים

בצד השמחות, רקע ונוסח נשמרים בנפרד ומשויכים לקטגוריה. כרטיס מוכן הוא צירוף של רקע ונוסח, והלקוח יכול לעבור בתוכו לכל נוסח שפורסם באותה קטגוריה ובאותו גודל (`src/lib/wording.ts`).

1. בעמוד התבניות, תחת "מה יוצרים", בוחרים "נוסח לבחירה בכרטיסים", קטגוריה וגודל. בעורך מסמנים כל שדה של שם, תאריך או מקום כ"פרט של הלקוח": מה שהלקוח כתב בו נשאר כשהוא מחליף נוסח, לפי שם השדה. לכן שמות השדות צריכים להיות זהים בכל הנוסחים של הקטגוריה.
2. יוצרים תבנית עם תמונת רקע באותה קטגוריה וגודל, ובוחרים לה נוסח בפאנל "בחירת נוסח". רק כרטיס שיש לו נוסח מציע ללקוח להחליף נוסח, ותבניות ישנות לא משתנות.
3. כדי שהלקוח יוכל להחליף גם רקע, מסמנים "הלקוח יכול להחליף את התמונה" ובוחרים קטגוריית תמונות. מוצגים רק רקעים באותן פרופורציות.

צבע הטקסט מותאם לרקע שמתחתיו בכל החלפת נוסח או רקע (`src/lib/fitColor.ts`): צבע המעצב נשאר אם הוא קריא, ואחרת נבחר גוון מתוך צבעי הרקע.

### סט לאירוע

בעמוד של קטגוריה פרטית שיש בה סדרה, הלקוח כותב את הפרטים פעם אחת, בוחר צבעים ומסמן אילו פריטים הוא צריך, ורואה כל פריט כמו שייצא (`src/components/EventSet.tsx`). השדות נלקחים מטקסטים שסומנו "פרט של הלקוח". אחרי היצירה כל פריט נערך בנפרד, ושינוי באחד לא עובר לאחרים.

### מדבקות

בעמוד "קטגוריות ותמונות" מסמנים קטגוריה כ"מדבקות", ומוסיפים לכל תמונה תגיות: שם הקטגוריה שהיא מתאימה לה, או `כללי`, ומילים לחיפוש. לקוח יכול להוסיף מדבקה, להזיז, להגדיל, לסובב ולמחוק, והשרת מקבל רק תמונות מספריית המדבקות, עד 12 בעיצוב. הכפתור "תכינו לי מודעה" בוחר מדבקה לכל מודעה לפי התגיות. `npm run seed:stickers` יוצר ספרייה התחלתית של 56 מדבקות, ו-`-- --remove` מוחק אותה.

### כניסה בלי הרשמה

מי שמתחיל לעבוד בלי חשבון הופך לאורח: משתמש רגיל עם `guest: true` מאחורי session רגיל, שנוצר רק כשצריך (`/api/auth/guest`). בהרשמה המשתמש נשאר אותו משתמש, ובכניסה לחשבון קיים העיצובים, הקטלוג והתמונות עוברים אליו (`src/lib/guest.ts`). העוזר ו"תכינו לי מודעה" דורשים חשבון, כי כל בקשה עולה כסף.

`npm run seed:wording-pilot` יוצר פיילוט של "שלום זכר" עם רקעים ונוסחים זמניים, כטיוטות שלקוחות לא רואים. `-- --remove` מוחק אותו.

## תוכן התחלתי

`npm run seed:content` יוצר את המודעות, הלוגואים, עיצובי השבת, הברכות והסט לשמחה, יחד עם התמונות שלהם מ-`scripts/seed-assets/`. הרצה חוזרת מדלגת על מה שקיים. `-- --draft` יוצר טיוטות, `-- --force` כותב מחדש את העיצובים, ו-`-- --force=ad:` רק את אלה שהמפתח שלהם מתחיל כך. עיצוב שלא השתנה לא נכתב, ותמונת התצוגה שלו נשארת. תמונת התצוגה נוצרת בפעם הראשונה שמנהל פותח תבנית בעורך.

## עוזר AI בעורך

בעורך יש תיבת "עוזר עיצוב": כותבים בקשה בשפה חופשית והעוזר משנה את הכרטיס דרך כלים מוגדרים (`src/lib/agent/tools.ts`).

- לקוח: העוזר ממלא רק שדות טקסט שסומנו לעריכה ומחליף רק תמונות שסומנו להחלפה. בשרת התוצאה עוברת שוב דרך `applyCustomerEdits`.
- מנהל (בתבנית): העוזר יכול להוסיף, להזיז, לעצב ולמחוק אלמנטים, ולסמן שדות לעריכה.
- מודעה של עסק: העוזר מקבל את המקצוע ואת פרטי העסק, מציע כיוונים ושואל עד שלוש שאלות, ולא ממציא מחירים, מספרים או המלצות.
- כל תשובה של העוזר נכנסת לעורך כשינוי אחד, כך ש-Ctrl+Z מבטל אותה, והשמירה האוטומטית שומרת אותה.

**התחברות:** העוזר רץ דרך Claude Agent SDK (`src/lib/agent/run.ts`). בפיתוח הוא משתמש בהתחברות של Claude Code במחשב הזה, בלי מפתח API. ההתחברות הזו מיועדת לפיתוח בלבד. בפרודקשן מגדירים `ANTHROPIC_API_KEY`, והחיוב עובר ל-API. בלי המפתח העוזר מוסתר בפרודקשן. `AGENT_MODEL` ו-`AGENT_EFFORT` מחליפים את המודל ואת רמת המאמץ (ברירת מחדל: Sonnet 5.5, medium). `npm run eval:agent` משווה בין מודלים על תרחישים קבועים, ו-`AGENT_ENABLED=false` מסתיר את העוזר.
