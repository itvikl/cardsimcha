# סטודיו עיצוב

אפליקציית Next.js ליצירת עיצובים מקטגוריות ותמונות. השלב הנוכחי: ניהול קטגוריות ותמונות ועורך ידני (בלי AI).

## הרצה

```
npm install
npm run dev      # http://localhost:3000
```

הנתונים נשמרים מקומית בתיקייה `data/` (קובץ `db.json` ותיקיית `uploads/`). התיקייה לא נכנסת ל-git.

## משתמשים והרשאות

**ההתחברות פעילה.** לפיתוח בלבד אפשר להריץ עם `AUTH_DISABLED=true`: כל מבקר הוא אז אורח אנונימי שנזכר לפי עוגייה בדפדפן, ויכול לעבור ל"מצב ניהול" בכפתור בסרגל העליון. בבילד של פרודקשן ההגדרה הזו לא פועלת.

- נרשמים ב-`/login`. **מנהל הוא רק מי שנרשם עם האימייל שב-`ADMIN_EMAIL`**, ולכן מגדירים את המשתנה לפני ההרשמה.
- מנהל: בונה תבניות, מסמן אילו טקסטים הלקוח יכול לערוך (ומה שם השדה), מפרסם או מבטל פרסום, מנהל קטגוריות ותמונות.
- לקוח: רואה תבניות שפורסמו, מתחיל מהן כרטיס משלו ועורך בו רק את השדות שסומנו. ההגבלה נאכפת בשרת (`applyCustomerEdits` ב-`src/lib/canvas.ts`), לא רק בממשק.

## מבנה

- `/categories` — יצירת קטגוריות, העלאת תמונות לכל קטגוריה (גרירה או בחירה), שינוי שם ומחיקה.
- `/` — רשימת העיצובים ויצירת עיצוב חדש (A4, A5, ריבוע, סטורי).
- `/editor/[id]` — עורך קאנבס: טקסט (עברית RTL), מלבנים ותמונות מהקטגוריות; גרירה, שינוי גודל, סיבוב, שכבות, שכפול, ביטול/חזרה, שמירה אוטומטית וייצוא PNG ב-300dpi.

## קבצים מרכזיים

- `src/lib/types.ts` — מבנה הנתונים ומסמך הקאנבס (מידות במ״מ).
- `src/lib/canvas.ts` — ולידציה של מסמך הקאנבס, גדלי עמוד ופונטים.
- `src/lib/db.ts` — שכבת האחסון המקומית. כל הגישה לנתונים עוברת דרכה, כדי שאפשר יהיה להחליף ב-MongoDB ו-Cloud Storage לפי האפיון.
- `src/components/Editor.tsx` — העורך.
- `examples/ad-import/` — כלי להמרת מודעות שטוחות (JPG) לתבניות עם טקסטים שאפשר לערוך, עם שתי מודעות לדוגמה.

## ערכת מותג לעסק

ב-`/business/brand` עסק שומר לוגו, צבעים ופרטים (`src/lib/brand.ts`, ערכה אחת לכל משתמש). מנהל מסמן בעורך אילו אלמנטים בתבנית מקבלים פרט, צבע או לוגו מהערכה. בדלת העסקית העיצובים מוצגים עם המיתוג של המשתמש, והעותק שנפתח מקבל אותו בשרת (`useBrand` ב-`POST /api/projects`). לוגו נשמר כתמונה בקטגוריה פרטית של בעליו (`brand:<userId>`), ו-`visibleImages` מסתיר אותו ממשתמשים אחרים.

### לוגו

בקטגוריה "לוגו" עסק בוחר תבנית, והשם והצבעים מתמלאים מהערכה. הכפתור "זה הלוגו שלי" בעורך שומר את העיצוב כ-PNG בלי רקע ובלי שוליים ומכניס אותו לערכה.

## מודעות והודעות לפי מקצוע

`src/lib/professions.ts` מחזיק לכל מקצוע את כאבי הלקוח, ההצעות, מה אסור לטעון, נוסחי המודעות והודעות הפרסום. **הנוסחים הם טיוטה, והלקוח צריך לאשר אותם**, במיוחד במשכנתאות.

- **סדרה:** תבניות עם אותו שדה `series` נלקחות יחד לסלסלה (`POST /api/projects/series`).
- **הודעות:** ב-`/business/messages` העסק מתאים הודעה ומעתיק אותה. האתר לא שולח שום דבר בשם העסק.
- **צבעים קריאים:** תפקידי הצבע `onPrimary` ו-`onSecondary` נותנים שחור או לבן לפי הצבע של העסק.

## זמני שבת

`src/lib/shabbat.ts` מחשב בשרת את השבת הקרובה לפי עיר, ו-`src/lib/shabbatDoc.ts` מחזיק את טבלת הערים. הזמנים נכתבים לעותק בשרת, והלקוח לא יכול לשנות אותם. עיצוב של שבת שעברה לא ניתן להורדה.

- **לפני השקה:** הטבלה היא טיוטה, ו**צריך אישור הלכתי לכל עיר**. החישוב היום לפי גובה פני הים, ויציאה בדקות אחרי השקיעה. לוחות מקובלים מחשבים לפעמים אחרת, ובירושלים נמצא הפרש של כמה דקות.
- **רישיון:** `@hebcal/core` הוא GPL-2.0. הוא רץ רק בשרת, ואסור לייבא אותו לקוד של הדפדפן.
- **סרטון:** `POST /api/projects/[id]/video` מרכיב ב-ffmpeg את הרקע מ-`public/shabbat/` עם שכבה שקופה מהעורך. בשרת צריך ffmpeg ב-PATH, או נתיב ב-`FFMPEG_PATH`.

## תשלום

**התשלום כבוי כברירת מחדל:** כל ההורדות חינם והמחיר רק מוצג. הוא נדלק כש-`BILLING_PROVIDER` מוגדר.

- `sandbox` הוא ספק בדיקות שלא גובה כסף. בבילד של פרודקשן הוא לא פועל, אלא אם מוסיפים `BILLING_ALLOW_SANDBOX=true`, שמיועד לבדיקה מקומית בלבד.
- **ספק אמיתי עוד לא מחובר.** ההוראות לחיבור נמצאות בראש `src/lib/billing.ts`. פרטי אשראי לא מגיעים לאתר.
- `SUBSCRIPTION_PRICE` קובע את מחיר המנוי (ברירת מחדל 149 ₪).
- **גבול האכיפה:** השרת מחליט אם מותר להוריד, אבל התמונה נוצרת בדפדפן, ולכן מי שעובד עם כלי המפתחים יכול לעקוף את זה. הסרטון נוצר בשרת, ושם אין עקיפה כזו.

## תוכן התחלתי

`npm run seed:content` יוצר את המודעות, הלוגואים, עיצובי השבת, הברכות והסט לשמחה, יחד עם התמונות שלהם מ-`scripts/seed-assets/`. הרצה חוזרת מדלגת על מה שקיים. `-- --draft` יוצר טיוטות, ו-`-- --force` כותב מחדש את העיצובים. תמונת התצוגה נוצרת בפעם הראשונה שמנהל פותח תבנית בעורך.

## עוזר AI בעורך

בעורך יש תיבת "עוזר עיצוב": כותבים בקשה בשפה חופשית והעוזר משנה את הכרטיס דרך כלים מוגדרים (`src/lib/agent/tools.ts`).

- לקוח: העוזר ממלא רק שדות טקסט שסומנו לעריכה ומחליף רק תמונות שסומנו להחלפה. בשרת התוצאה עוברת שוב דרך `applyCustomerEdits`.
- מנהל (בתבנית): העוזר יכול להוסיף, להזיז, לעצב ולמחוק אלמנטים, ולסמן שדות לעריכה.
- מודעה של עסק: העוזר מקבל את המקצוע ואת פרטי העסק, מציע כיוונים ושואל עד שלוש שאלות, ולא ממציא מחירים, מספרים או המלצות.
- כל תשובה של העוזר נכנסת לעורך כשינוי אחד, כך ש-Ctrl+Z מבטל אותה, והשמירה האוטומטית שומרת אותה.

**התחברות:** העוזר רץ דרך Claude Agent SDK (`src/lib/agent/run.ts`). בפיתוח הוא משתמש בהתחברות של Claude Code במחשב הזה, בלי מפתח API. ההתחברות הזו מיועדת לפיתוח בלבד. בפרודקשן מגדירים `ANTHROPIC_API_KEY`, והחיוב עובר ל-API. בלי המפתח העוזר מוסתר בפרודקשן. `AGENT_MODEL` ו-`AGENT_EFFORT` מחליפים את המודל ואת רמת המאמץ (ברירת מחדל: Sonnet 5.5, medium). `npm run eval:agent` משווה בין מודלים על תרחישים קבועים, ו-`AGENT_ENABLED=false` מסתיר את העוזר.
